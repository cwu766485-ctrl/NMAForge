# NMAForge-V1.2 Round 16 — Four-Layer GPT-2-like Top Integration

## Result

**Disposition: `PARTIAL`.** A four-layer H64 decoder forward graph now runs on one unreset `ai_accel_top` instance for fixed prompts of one and four tokens. Layer outputs are handed to the next layer through SPAD, each layer has its own persistent K/V allocation, and the final LayerNorm plus a 256-wide LM head is checked against generated INT32/INT8 golden data. No product RTL was changed.

This is a functional test of a deterministic synthetic-weight decoder. It is not a trained GPT-2 model, and it does not perform autoregressive feedback: the host does not choose a token from logits and submit it to another decode step. The full four-layer session latency including all later-layer weight DMA, model/input setup and host orchestration is therefore **not reported as a single measured end-to-end number**.

### Allocation evidence

The planner reserves a 128 KiB, four-bank SPAD map:

| Region | Byte range (half-open) | Size |
|---|---:|---:|
| Data/weight/activation/KV arena | `0x01000–0x16000` | 86,016 B available; allocator high-water `0x14400` |
| CMDQ, 512 × 64 B | `0x16000–0x1E000` | 32,768 B |
| CPLQ, 512 × 16 B | `0x1E000–0x20000` | 8,192 B |

Four distinct K/V pairs occupy `0x01000–0x03000`, 1,024 B per K or V tensor (8,192 B total); these session-lifetime buffers are never aliased. Weight payloads are streamed by layer and the final LM head by N-tile. Temporary activations and scratch reuse addresses only when their modeled descriptor lifetimes do not overlap. The proof reports zero violations for pairwise address/lifetime overlap, 64-byte alignment, arena bounds and queue overlap. There is 7,168 B between the allocation high-water and CMDQ base.

| Cache | Address range | Bytes | Lifetime |
|---|---:|---:|---|
| Layer 0 K / V | `0x01000–0x01400` / `0x01400–0x01800` | 1,024 each | Whole session |
| Layer 1 K / V | `0x01800–0x01C00` / `0x01C00–0x02000` | 1,024 each | Whole session |
| Layer 2 K / V | `0x02000–0x02400` / `0x02400–0x02800` | 1,024 each | Whole session |
| Layer 3 K / V | `0x02800–0x02C00` / `0x02C00–0x03000` | 1,024 each | Whole session |

The machine-readable proof retains `rtl_execution=NOT_RUN` because that artifact is a software allocator proof. Product Top use of its generated layout is established separately by the VCS handoff, descriptor, DMA-fence and Golden checks.

## Implementation and limitations

- Software changes parameterize the existing H64 layer generator and add an interval/liveness allocator plus a four-layer workload preparation flow.
- The testbench publishes each layer's descriptors to the existing Product Top queues, services its real AXI4 weight DMA and completion fences, reads the previous layer's actual SPAD output for checking, and points the next layer's first residual descriptor directly at that SPAD output. It does not write the hidden handoff tensor back into SPAD.
- Final LayerNorm and LM Head run as Product SFU/Requant/GEMM descriptors. The testbench clears padded causal-softmax destination rows as runtime initialization before their producer; this is not an intermediate compute result.
- **Not demonstrated:** four-layer autoregressive token generation; model training or language quality; a production software runtime; a single complete inference latency including all per-layer DMA and host costs; 128 KiB operation on all other Top workloads; TinyNPU comparison; ASIC area/timing/power.
- No changes were made to `main`, another worktree, product RTL, PDKs, SRAM libraries or license files.
