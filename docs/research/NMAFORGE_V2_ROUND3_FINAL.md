## Gate 1 — H64 legal tiling and first RTL projection

The executable workload tiles one H64 Q projection into four ABI-v7.4 GEMM
commands. Each command uses `M=16,N=16,K=64`, `k_words=16`, and owns one
16-column output region. The 64-byte descriptor images, input/weight memory
image, completion entries, poison outputs and independent INT32 Golden are
generated by `benchmark/gpt2_compat/generate_h64_projection.py`.

```text
H64_PROJECTION_GENERATOR_PASS descriptors=4 shape=16x16x64 golden_words=1024 high_water=38912
REPRESENTATIVE_MODEL_PASS desc=4 golden_words=1024 useful_macs=65536 command_cycles=1188
  preloaded_spad_bytes=9536 spad_read_bytes=8192 spad_write_bytes=4096
```

The real Top checked all 1,024 output words and completion records. The four
live token rows are nonzero; twelve physical rows are explicit zero padding.
The SPAD high-water mark is 38,912 bytes, within 128 KiB. Result: `PASS` for a
single H64 Q projection only.

Reproduce:

```sh
cd /tmp/nmaforge-v2-round3-h64
make -C dv/subsystem/top_smoke/sim ai_h64_projection_top \
  AI_H64_PROJECTION_RUN=/tmp/nmaforge_h64_projection_round3_replay \
  AI_H64_PROJECTION_SEED=20261114
```

## Gate 3 — SVSE vector product-arithmetic comparison

The research SVSE adapter runs parameterized vectors through real SPAD read,
buffered compute and ordered writeback. Both DUTs use the product's actual
`ai_tensor_sfu_core` and the same deterministic registered-response/backpressure
memory model. All output memory words matched.

| Operation, length 4 | Product SFU cycles | SVSE cycles | Product reads/writes | SVSE reads/writes |
|---|---:|---:|---:|---:|
| Residual I32 | 40 | 46 | 8 / 4 | 8 / 4 |
| Requant I8, shift 5 | 22 | 30 | 4 / 4 | 4 / 4 |

Abort/read drain, writeback accepted prefix, epoch drain and nonzero stall/wait
counters were exercised. SVSE is 15.0% slower for Residual and 36.4% slower
for Requant, with identical SPAD transaction counts. Decision:
`REWORK_FOR_PRODUCT`; there is no measured optimization benefit yet.

Reproduce:

```sh
cd /tmp/nmaforge-v2-round3-svse
make -C dv/research/dams_svse/sim adapter
make -C dv/research/dams_svse/sim all
```

Detailed evidence: `docs/research/ROUND3_SVSE_VECTOR_SPAD_AB.md`.

## Gate 4 — DAMS ownership and concurrency decision

No DAMS product integration was attempted. Product RTL already supports one
active slot per engine, sequential descriptor issue to other idle engines,
and in-order completion retirement through the existing dispatcher FIFO.
Cross-descriptor RAW/WAR/WAW responsibility remains with software. Ordinary
SPAD clients share the owner-preserving `ai_compute_spad_mux` and one
scheduler-side core port; Matrix/CNM also use their existing atomic banked or
line paths. `ai_parallel_compute_dispatcher` uses engine-level readiness, not
bank-mask reservations.

The research DAMS prototype tracks bank masks, not transaction IDs, address
ranges, response owners or committed-write prefixes; epoch flush clears its
reservations. Its abstract test therefore cannot establish a real-engine
concurrency gain or fault-safe product integration. Decision:
`REWORK / NOT_INTEGRATED`. A next DAMS experiment must instrument a real legal
descriptor pair and show an overlap/stall window that the current dispatcher
cannot already exploit before adding scheduling logic.

Detailed RTL contract review: `docs/research/ROUND3_DAMS_PRODUCT_CONTRACT_AUDIT.md`.
