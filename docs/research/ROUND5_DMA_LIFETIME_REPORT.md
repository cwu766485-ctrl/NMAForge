# NMAForge v2.0 Round 5 DMA and Lifetime Evidence

This report is for the isolated branch `research/nmaforge-v2-round5`, based on
`974eff43632bb7ec6e82a0b8470064de11dff3d7`. It does not change the product
branch or the Legacy ABI.

## Measured RTL workload

The workload is generated by
`benchmark/gpt2_compat/generate_h64_ffn_tile.py` and executed by the real
`ai_accel_top` Product Top. It contains four nonzero H64 rows padded to a legal
16x16 Matrix tile, a streamed 64x16 FFN-up weight tile, GELU, packed Requant,
a 16x16 FFN-down tile, and Residual 2. The five descriptors are serialized by
the existing ABI event chain.

| item | value |
|---|---:|
| useful model MACs | 5,120 |
| physical executed MACs | 20,480 |
| padding MACs | 15,360 |
| useful output elements | 64 |
| physical output elements | 256 |
| DMA segments | 4 |
| external DMA payload | 3,648 bytes |
| DMA busy | 965 cycles |
| command cycles | 4,684 |
| end-to-end including DMA | 5,789 cycles |
| SPAD reads / writes | 6,656 / 4,352 bytes |
| Golden words checked | 1,088 |

The DMA payload contains input, descriptors, both weight tiles, and the
residual source. Output and intermediate regions are initialized to the poison
value by the testbench only; no Python-computed FFN output is loaded. The
testbench waits for each DMA transaction to report completion before publishing
the CMDQ doorbell, so the demonstrated dependency is real DMA completion to
compute start. It is not yet an in-command per-tile streaming scheduler.

## SPAD ranges

The generated manifest records all ranges in
`/tmp/nmaforge_round5_ffn_tile_rtl_20261115_v2/workload/manifest.json`.
The highest active address is `0x3100` (12,544 bytes), well inside 128 KiB.
Input and streamed weight tiles remain live through their consuming GEMM;
GEMM output remains live through GELU; GELU output remains live through
Requant; packed output remains live through FFN Down; Down output and the
residual source remain live through Residual 2. No live range aliases another.

## Boundary

The first incomplete node for a complete Decoder Block is the full 64->256
FFN-Up schedule with per-16-channel weight DMA interleaved with compute. The
current Product Top has no descriptor contract that makes a sequence of DMA
completion events and Matrix tiles one ordered command graph while retaining
the existing dispatcher ownership rules. FFN Down over all 256 channels,
KV-cache lifecycle, four layers, final LayerNorm/LM Head, and persistent decode
are therefore `NOT_RUN`; no system-level Decoder claim is made.
