### Latest CP mixed error/abort/reset-word sweep (2026-10-18)

SPEC, or ABI changes), the Command Processor UVM coverage run exercised all
2 prefix-error kinds × 3 abort-delay classes × 4 completion reset cut points
(`0..3` accepted SPAD words), over three seeds. The final canonical target
passed 72/72 full-suite runs; each run passed `31/31` scenario bins and had
UVM warning/error/fatal=`0/0/0`. A separate focused replay passed all four

100%; the new `cp_mixed_reset_words` point was 4/4 and the new
`cp_mixed_kind_delay_reset_cross` was 24/24. URG assertions had 11 successes,
0 failures/incomplete, 2 UVM RAL no-attempts, and both cover properties

completion attempt from an accepted word0, which is invalid when reset occurs
before word0; the checker now counts `completion_start` separately from
accepted SPAD words. The first merged report also exposed a stale aggregate
count gate; the final rerun used the measured totals and explicit new-bin
gates. This closes the tested mixed prefix-error / compute-abort / reset-word
cross only; arbitrary timing, broader V2 lifecycle interactions, residual RTL
coverage disposition, and V5 closure remain open.

## 2026-10-18 CP reachable fetch/macro abort coverage

Starting from baseline HEAD `189cd2a5f4a0d2542387e9b3b5a6169cc175d804`,
the CP UVM coverage extension exercised three reachable abort paths within
the existing `CP_FETCH_ABORT` and `CP_MACRO_CHILDREN` scenarios; no scenario
enum or product RTL/SPEC/ABI changed. `fetch_busy` in the behavioral endpoint
tracks request acceptance through response, and is released on completion,
error, or reset. The direct path asserts abort on the same sampled cycle as
`fetch_done` in `ST_FETCH` with `abort_pending=0`. The two macro paths abort
while fetching a child descriptor and while the child is in decode. Each
macro path checks that the single `ERR_ABORT` completion belongs to the parent
task ID, no child compute launch occurs, and queue pointers retire exactly
once.
