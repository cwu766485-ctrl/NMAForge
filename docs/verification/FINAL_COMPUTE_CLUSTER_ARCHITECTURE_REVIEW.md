# Final Compute Cluster Architecture Review

**Review baseline:** tested RTL `fc60f95d72c0cfb7dfa9df895a30a701c842d21e`
**Candidate:** PR #7, `candidate/frontend-closeout`; this review does not approve or merge it.
**Product defaults:** `SPAD_WORDS_PER_BANK=8192`, four banks, one 16×16 INT8 Matrix array (256 MAC lanes).
**Decision:** architecture is reviewable as a bounded digital accelerator baseline, but Compute Cluster DV closure and ASIC mapping remain HOLD. No confirmed functional RTL bug was established by this document-only review.

## Scope and evidence

The review follows `rtl/top/ai_accel_top.v` into `ai_accel_compute_cluster`, `ai_compute_spad_mux`, `ai_spad_arbiter`, `ai_scratchpad`, descriptor/queue control, DMA and the seven engine implementations. Requirement language is taken from Compute Cluster SPEC v1.8, NPU Architecture v2 SPEC and the final architecture specification. Where they disagree, the status is recorded in [RTL/SPEC gap analysis](RTL_SPEC_GAP_ANALYSIS.csv); no ABI interpretation is silently changed.

The selected source contains one RTL change at `fc60f95`: request selection and response-owner routing are separated in `rtl/top/fabric/compute/ai_compute_spad_mux.v`. The later PR #7 commits through `f919bb7` add evidence/docs and one validator testbench correction; `rtl/` is unchanged over that interval. The candidate worktree was inspected read-only. A new review branch was created from the requested tested SHA. References below to `frontend_closeout` reports are evidence from the later PR #7 candidate bundle, not files present at this exact-SHA review tree.

Six actual-RTL diagrams are in [Compute Cluster Block Diagram](COMPUTE_CLUSTER_BLOCK_DIAGRAM.md). The macro-visible storage and collision requirements are separated from behavioral RAM behavior in [SPAD Macro Contract](SPAD_MACRO_CONTRACT.md). ## Architecture findings

1. `ai_accel_top` owns AXI-Lite control, command/completion queues, the 128-bit AXI4 DMA, scratchpad protection/arbitration, the four-bank memory, and integration routing. `ai_accel_compute_cluster` is structural: seven engines receive latched launch fields and return independent busy/done/error/result/cycle/element vectors. The one active top clock is `aclk`; `aresetn` is asynchronous active-low. See `rtl/top/ai_accel_top.v:24`, `:595`, `:1194`, `:1266`, `:1406` and `rtl/top/fabric/compute/ai_accel_compute_cluster.v:166`.
2. Seven different engines may be busy together, with one active slot per engine. The dispatcher captures each done result into that engine's unique descriptor slot, accepts simultaneous done bits, and retires only the FIFO head. This is real RTL capability, not a promise of simultaneous SPAD service. See `rtl/control/queue/ai_parallel_compute_dispatcher.v:136`, `:190`, `:395` and SPEC v1.8 REQ-PC-001..005.
3. The seven ordinary 32-bit clients are serialized by `ai_compute_spad_mux`; its one selected owner is retained through request-ready, protection error and response. Matrix line access and the Matrix/CNM banked paths bypass that scalar sub-mux but still enter the sole `ai_spad_arbiter`. Matrix banked and CNM four-lane requests share its banked RR class and receive distinct tags 3 and 5. See `rtl/top/fabric/compute/ai_compute_spad_mux.v:3`, `rtl/memory/ai_spad_arbiter.v:47`, `:81`, `:97`, `:112` and SPEC v1.8 REQ-PC-006/007.
4. `ai_spad_arbiter` has descriptor then completion control priority, followed by round-robin service among core, banked/CNM and DMA classes. The banked/CNM class admits one transaction per turn; an admitted CNM transaction can address any subset of four physical banks, with per-lane valid/ready/response mask. This is not independent per-bank arbitration between requesters. See `rtl/memory/ai_spad_arbiter.v:76`, `:97`, `:131`, `:178`.
5. SPAD defaults to 4 × 8192 × 32-bit = 131,072 data bytes (128 KiB), with one parity bit per word in the VCS behavioral model. The 32768-word/bank, 512 KiB mode remains an allowed parameterized compatibility profile. The checked-in `NPU_ARCHITECTURE_V2_SPEC.md` still calls 512 KiB the unchanged capacity at lines 33 and 319; the RTL default and final architecture spec call 128 KiB product default. Classify as stale baseline text pending spec owner reconciliation, not an RTL change request. See `rtl/top/ai_accel_top.v:24`, `:162` and `rtl/memory/ai_scratchpad.v:11`, `:149`.
6. The memory simulation branch, FPGA XPM branch and a future ASIC macro wrapper are not interchangeable evidence. Behavioral VCS supports explicit parity fault observation; the XPM branch returns parity-error outputs as zero. The XPM model requests two-cycle read latency and read-first mode. A foundry macro with one port, no parity, different read latency or undefined same-address collision is not a drop-in implementation. Mapping is `ASIC_MAPPING_BLOCKED`; no macro wrapper, authorized SRAM library, or characterized project SDC is available in the public checkout.
7. Engine read responses are registered, in order and have no response-ready or transaction ID at the local engine interface. The scratchpad data contract is two registered cycles; the arbiter pipelines owner/error metadata to match it. A client cannot accept arbitrary out-of-order responses. Matrix has a four-entry read metadata path by default; Mixed FP has two operand-pair slots; other depths must be treated per engine rather than inferred from Matrix. See SPEC v1.8 sections 2.3–2.5 and 3.7.
8. Reset clears local engine/owner/queue valid state. It does not create an AXI fabric epoch tag. If an accepted external AR/AW/W is outstanding, SPEC v1.8 requires coordinated accelerator and owning-fabric reset, or explicit DMA drain/isolation before accelerator-only reset. External-fabric reset compliance is still an integration verification item.

Across all seven, busy/done/error/code/result/cycle/elements are separate vectors in the structural wrapper. The dispatcher stores completion ownership by engine slot; a legacy OR-priority `core_done` view also exists for the serial compatibility path. Tests must drive and check both paths and must not infer vector completion identity from the aggregate status signals (`ai_accel_compute_cluster.v:166`, `:184`).

All seven engine blocks use asynchronous active-low reset and return to their idle control state; accepted SPAD data is not rolled back by reset. Each block has a local abort/error path, but priority is engine-specific and is defined by Compute Cluster SPEC v1.8 §4 rather than a shared wrapper rule. KV is called out above: watchdog > abort > merged SPAD error. Matrix, CNM, SFU, Conv, Scalar and Mixed FP require their own priority-row tests; no common rule is inferred from the cluster wrapper. Reset/fabric epoch for outstanding external AXI transactions is a top-level coordinated-reset contract, not an engine property.

## Commands, completion and output semantics

Parallel CMDQ dispatch is FIFO-issue and FIFO-retire, not completion-order retirement. One active task per engine is stored in its slot; different engine work may overlap. A bounded eight-entry dispatcher result FIFO stores task IDs, result/error/cycles/elements and completion-required metadata (`ai_parallel_compute_dispatcher.v:134`, `:207`). Each completion comprises four 32-bit words. `CPLQ_TAIL` advances only after the writer reports all four writes complete; busy-time software `CPLQ_HEAD` advancement is supported by SPEC v1.8. Events become visible on successful ordered retirement. Reset discards unpublished entries.

For writes, accepted means `valid && ready`; already accepted stores remain visible after abort/fault/reset. Ordered output engines must leave a contiguous committed prefix and must not commit later elements after an earlier failed element. This is not rollback/transactional memory. Matrix line writes are whole 16-byte transactions and SPEC v1.5 requires full WSTRB; see SPEC v1.8 §4.2.3.

## ABI and profiling consistency

The software descriptor remains ABI v7.4: 64 bytes, 16 little-endian 32-bit words. Word 0 carries task ID/opcode; words 1–4 carry operand/bias/destination fields; 5–7 shape/length/flags; 8–9 auxiliary/postprocess; 10–12 strides; 13 batch/head; 14 dependency events; 15 version/clear. Opcode-specific legality is in `ai_descriptor_validator` and the normative `docs/spec/SPEC_ZH.md`, not inferred solely from which core has an `op_mode` case. `0x52/0x53` are additive v2 Matrix operations; `0x50/0x51` are mixed FP. Queued invalid descriptors must fail before any operand request or output side effect.

Completion ABI is 16 bytes/four 32-bit words: task ID, status/error, result, element count. Software publishes CMDQ_TAIL and consumes CPLQ_HEAD; hardware advances CMDQ_HEAD and only advances CPLQ_TAIL after all four words are accepted. DMA is a separate 128-bit AXI4 data master with 64-bit addresses, 4-bit IDs, up to 16 beats per burst, 4 KiB splits and up to four tagged read requests as configured by the top contract. DMA AXI IDs are not compute-SPAD response IDs.

Every engine returns `cycle_count` and `element_count` to the dispatcher task record; the completion ABI does not include a cycle field. Top CSR profiling is selective: Matrix active/stall/cycle metrics and DMA byte/request/stall/outstanding counters are present; Matrix controller diagnostic stall counters and CNM local/global/prefetch counters are not all software ABI fields. Each counter's increment event and enable need a separate definition before comparing performance across engines. See `rtl/top/ai_accel_top.v:250..264`, `:1244..1259`, and `rtl/top/fabric/compute/ai_accel_compute_cluster.v:133..141`.

## Physical feasibility and closure decision

`ASIC_MAPPING_BLOCKED` remains true. `eda.yaml` identifies top/filelist and a private PDK root, but the public source tree has no authorized TSMC28 target libraries, compatible 128 KiB macro timing/behavior views, wrapper, or constrained clock SDC. Current design assumes one common `aclk`; functional 4 ns/250 MHz labels in simulation are not timing closure. Required next artifacts are a legal macro contract and adapter, target `.db/.lib` and Verilog view, characterized read/write collision and byte-mask semantics, project SDC and corners, DC mapped netlist, MMMC STA and power activity annotation; then DFT/MBIST, APR, extraction, IR/EM and physical verification. The later PR #7 evidence bundle (outside this exact-SHA tree) reports 467 SpyGlass lint warnings and two CDC structural warnings, with no blanket waiver; full RDC stopped without a final goal summary. See the PR #7 `docs/verification/frontend_closeout/STATIC_REVIEW.md` evidence and [SPAD Macro Contract](SPAD_MACRO_CONTRACT.md).

Reproduction commands and logs are in the later PR #7 evidence bundle (`benchmark/verification/frontend_closeout/manifest.json` in that candidate, absent from this review tree); the old 512 KiB real-top fixture is explicitly invalid at default 128 KiB and remains a fixture issue, not grounds to truncate addresses.

## Freeze recommendation

Freeze the seven-engine boundary, opcode routing, owner tags, data formats, output prefix and queue ownership at the stated candidate SHA. Do not claim full DV closure until the P0/P1 items in the [Freeze Checklist](ARCHITECTURE_FREEZE_CHECKLIST.md) close. Reconcile stale 512 KiB normative text and publish the macro contract before claiming ASIC readiness. No additional engine or performance RTL change is needed to close the reviewed architecture.
