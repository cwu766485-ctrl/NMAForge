## Implementation

The `0x43` KV_WRITE ABI keeps descriptor size and the `flags=0` legacy path. New opt-in `flags=8'h01` adds a bounded Matrix-B token append mode for 4–16 INT8 features (multiples of four), token capacity 4–16 (multiples of four), and `src0_stride=16`. `aux0={head_index,token_index}` selects the destination. `src1_stride` is the per-head cache span.

The append mode reads packed Matrix-A source words, then performs a byte-lane read/modify/write into Matrix-B physical `[token,feature]` storage. This layout is the V operand layout consumed by AV. K continues to use the existing word-strided `0x43` copy into Matrix-B `[feature,token]` storage used by QK. `0x44` remains unchanged. Configuration is checked before entering the append sequence; the extension does not add a new opcode or a cache array.

The cluster now forwards descriptor flags to the KV engine. Existing direct KV testbench instances explicitly tie flags low. SPEC_ZH documents the opt-in contract. The Matrix Core was not modified.

The append FSM uses 4 state bits for 11 states, versus 3 bits for the prior 6-state FSM. New data/control registers are `source_word_r` (32), `token_index_r` (16), `scatter_capacity_r` (16), and `scatter_byte_shift_r` (5): 69 bits, plus 1 FSM state bit. Existing `data_r` holds the destination word during read/modify/write. There are no new storage arrays. This is an RTL register estimate, not mapped area; address arithmetic and variable divide/modulo validation also add combinational cost. ASIC/PPA was intentionally not run.

## Four-step incremental decode

The deterministic H16 model has 2 heads, head dimension 8, one layer, INT8, and cache capacity 8. Tokens 0–3 populate the cache; tokens 4–7 are appended in sequence. For each decode token, Top executes Q/K/V projection, K/V append, full cache readback, QK, causal Softmax, AV, output projection, residual, LayerNorm, and FFN. Each stage has a completion-ordered descriptor chain and remains resident in the same SPAD between stage submissions.

Token IDs 4–7 are supplied by the host; the selected embedding rows are placed in the input image. Projection and subsequent block computation are RTL operations. The weights are reproducibly generated by six small deterministic integer perceptrons, not a trained language model; their reported 16/16 projection-label fit is not language-model accuracy. This demonstrates incremental KV function, not autonomous next-token generation or language quality.

The QKV descriptor count remains six projection commands/token: `0x30` GEMM in the baseline or `0x52` GEMV in the alternate policy, followed by the same requant path. GEMV's measured gain is small because Matrix work is a small part of the token window; the long LayerNorm/Softmax/SFU path is unchanged. B-fold reuse is gated off for `M<=4` by the Matrix Core, so this M=1 experiment does not demonstrate a cache benefit. This run also did not vary a separate prefetch control; cache/prefetch ablation is therefore **not run**, not inferred from the GEMV result.

## Preserved baselines and regression

- Snapshot replay: 102 descriptors; 3,264/3,264 Golden words; 29,608 command cycles (21,030 prefill, 8,578 decode). The snapshot's KV image is preloaded and does not qualify as incremental decode.
- Top smoke: `make ai_smoke AI_RANDOM_CASES=20 AI_SEED=1616 SEED=1616` passed, including existing GEMM/GEMV, fused tile, KV protection, and reset-recovery checks.
- Legacy KV compatibility: 27 KV round trips, 7 KV fault cases, 10 address/config cases, 4/4 residual FSM transition checks, and reset recovery passed with flags tied low.
- No full UVM, coverage closure, ASIC synthesis, or PPA claim is made.

Mode-specific scatter abort/reset and invalid descriptor/no-partial-write tests remain open. The successful Top run verifies normal completion and correct cache preservation across appends; the legacy regression verifies the unchanged flags=0 behavior. An abort after a scatter has started may leave a partially updated token slot, so software must treat that token position as invalid and overwrite the complete K/V entry before consuming it. This recovery contract needs a dedicated focused test before broader sign-off.

## Secondary audit: CNN output layout

Round 16 made no CNN RTL change and did not rerun the CNN. Prior reported figures remain historical evidence only: Legacy four-command execution 61,310 cycles; first-layer fused full-output path 35,184 cycles; both-layer fused native Matrix-A output 9,050 cycles but incompatible with the required Row-Major output; both-layer fusion plus the prior conversion path 39,686 cycles and full-output compatible. The latter is 4,502 cycles slower than first-layer fusion, so the 9,050-cycle native-layout number is not a complete-output win.

The current `0x53` linearized output mode is constrained to `N=4`, `M<=64`, aligned output, one instance, and no transpose. It cannot emit the current large CNN's `M=512,N=16` Row-Major output. No general DMA layout converter was found in the active path. The minimal follow-up is an opt-in bounded row-major packed output mode on the existing Matrix writeback path, or a consumer contract accepting Matrix-A layout. The former needs row/tile and 128-bit output-lane addressing through all M/N tiles, explicit ABI validation, and Golden/traffic/cycle comparison; it should be costed before implementation. No general reshape engine is proposed here.

## TinyNPU comparison readiness

The pinned TinyNPU SHA is recorded in `round16_evidence/tiny_npu_benchmark_manifest.json`. Round 16 did not build or execute TinyNPU. A fair H16 comparison still requires: an executable common QKV/attention/FFN subgraph; identical INT8 weights, input token IDs, requant and saturation rules; matching per-stage Golden including cache updates; a common memory latency/bandwidth service; and separately reported compute-only versus controller/memory endpoints and SRAM capacities. The current NMAForge path uses a custom `0x43` append path while TinyNPU support for the same physical KV update contract has not been shown. Therefore no cross-project speedup is calculated.

## Reproduction

All commands run from the indicated simulation directories. Output directories must not already exist.

```bash
cd dv/subsystem/top_smoke/sim
make ai_h16_transformer_top \
  AI_H16_TRANSFORMER_RUN=/tmp/r16_snapshot \
  AI_H16_TRANSFORMER_PYTHON=python3.12 \
  AI_H16_TRANSFORMER_SEED=20261116

make ai_h16_incremental_decode \
  AI_H16_INCREMENTAL_RUN=/tmp/r16_gemm \
  AI_H16_INCREMENTAL_POLICY=gemm \
  AI_H16_INCREMENTAL_SEED=20261116

make ai_h16_incremental_decode \
  AI_H16_INCREMENTAL_RUN=/tmp/r16_gemv \
  AI_H16_INCREMENTAL_POLICY=gemv_qkv \
  AI_H16_INCREMENTAL_SEED=20261116

make ai_smoke AI_RANDOM_CASES=20 AI_SEED=1616 SEED=1616

cd ../../../block/compute/cnn_kv/sim
make random-latency-test SEED=20261116 OUT_DIR=/tmp/r16_kv_legacy
```

The incremental target regenerates weights and descriptors, compiles Top VCS with the 128 KiB behavioral SPAD configuration, runs persistent-SPAD stage batches, and checks completion and output memory against the independent Golden. VCS emits the known `LOOP-REROLL-ENABLED` debug-capacity warning from `ai_transformer_workload.svh`; no compile error occurred.
