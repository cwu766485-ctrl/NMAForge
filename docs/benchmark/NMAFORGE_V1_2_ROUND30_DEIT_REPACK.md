## Change and root cause

At base commit `70a5296d07e0ac3287bb73297cc5632e205a215a`, opcode `0x3B` source range validation used dense logical `M*N` bytes. The source is physically stored in sparse 4×4 Matrix-A tile address space, so the validated span must be `4*M*N` bytes for the padded shape. For M=208, N=192, that is 159,744 bytes, from `0x02000` to exclusive end `0x29000`.

The validator now checks the full padded physical span. A directed boundary test accepts the legal full source range and rejects a destination alias at `0x0d000`, which lies inside the physical source range but outside the old under-counted dense span. This is an address-protection correction; no Repack datapath behavior changed. `SPEC_ZH.md` records the range rule.

The full physical source interval and all destinations were disjoint and within the 256 KiB SPAD. The 197 valid rows and 11 padded rows were exercised; source padding was initialized with poison and destination padding followed the generator’s zero-fill contract. Independent Golden comparison was performed after Top execution.

Read/write traffic per run was 37,824/39,936 bytes. Q Dense and K-major loaded a 199,920-byte fixture image, including 161,904 bytes of test-only poison initialization, with 299,879 preload AXI cycles. V Matrix-B loaded 209,136 fixture bytes, including 171,120 poison bytes, with 313,703 preload AXI cycles. The measured command windows exclude preload (`dma_preload_included=0`). Therefore the Top smoke `end_to_end_cycles` values (338,856; 338,855; 352,679) include neither the prior preload nor host preparation and must not be used as application latency.

Repack commands report zero useful MACs. The synthetic source tensor is generated by the fixture formula in each workload manifest and was preloaded before command issue. It is not output from a Product RTL QKV projection.
